FROM CLI

从 CLI 说起

GUI（图形界面）
鼠标点来点去
  • 按钮、窗口、菜单，点击操作
  • 不需要输入任何命令
  • 但要额外绘制界面，更耗资源
CLI（命令行）
纯文本命令操作软件
  • Windows 常见终端：cmd、PowerShell
  • 工业界最常见的接口形式，省资源
  • 连接大规模服务器集群时，只有 CLI

新手不用背命令——让 CLI AI 编程工具帮你执行所有 CLI 操作：进文件夹、搜文件、跑项目，全靠对话完成。

VS AI IDE

和 AI IDE 有什么不同

类比 z.ai
一种特殊的 z.ai
  • 同样只要一个简单的对话入口
  • 自动为你执行所有需要的操作
  • 有时需手动打开浏览器查看最终效果
类比 AI IDE
相当于 IDE 里的 Agent 模块
  • 就是 IDE 侧边那块对话区域
  • 各 IDE 实现不同，能力差异大、效果不稳定
  • CLI 工具多由大厂直接开发：Anthropic、OpenAI

Claude Code 本身就是为 Anthropic 内部研发团队服务的工具，从一开始就围绕「满足工程师真实需求」设计。

CLAUDE CODE VS CURSOR

CLI 工具 vs IDE 内置 Agent

功能特性Claude CodeCursor更优者
自动任务执行✅ 非常强❌ 能力有限Claude Code
IDE 集成❌ 仅命令行✅ 原生 VS CodeCursor
实时代码补全❌ 无✅ 体验极佳Cursor
多文件操作✅ 非常强⚠️ 还不错Claude Code
GitHub 一体化操作✅ 可直接提交⚠️ 需要手动操作Claude Code
学习成本⚠️ 中等✅ 上手简单Cursor
上下文长度✅ 非常长⚠️ 较好Claude Code
调试辅助✅ 自动化⚠️ 较多需手动Claude Code

简单说：更长的连续对话、更长的上下文窗口、更快的响应（可接自定义模型 API）——编码操作上更聪明、更稳定。

THE TOOLKIT

首选组合：三大 CLI AI 编程工具

01
Claude Code
Anthropic 出品。通过 GLM 4.6 转发 API，体验接近 Claude 4，价格更便宜。
02
Codex
OpenAI 出品。使用 GPT-5，整体能力更强，响应快、犯错率低。

CLAUDE CODE

Claude Code 是什么，怎么装

它是什么
Anthropic 出品的终端 AI 编程工具
  • 终端为主，也支持作为 VS Code 插件
  • 深度理解整个代码仓库
  • 端到端完成任务：改代码、修 Bug、跑测试
  • 管理 Git 工作流：解决冲突、创建 PR
  • 极长上下文，适合沉浸式 vibe coding
三分钟装好
# 安装 Claude Code npm install -g @anthropic-ai/claude-code # 进入你的项目 cd your-awesome-project # 启动 Claude Code（Ctrl+C 退出） claude

觉得命令行安装麻烦？直接让 Trae 的 Agent 帮你完成安装。

官方直连成本高 → 实战中改用兼容 Anthropic 协议的国产模型 API。

BACKEND · GLM

后端方案一：智谱 GLM（推荐）

  • GLM-4.6 代码能力对标 Claude Sonnet 4，200K 上下文，国内第一梯队
  • 先获取 API Key：bigmodel.cn（国内版）/ z.ai（国际版）
  • 可以把配置命令直接交给 Trae 执行；配完必须重启 Trae，否则内置终端读不到新变量
# 在 Cmd 中运行以下命令（国内版 GLM） # 注意将 your_zhipu_api_key 替换为你刚获取的 API Key setx ANTHROPIC_AUTH_TOKEN your_zhipu_api_key setx ANTHROPIC_BASE_URL https://open.bigmodel.cn/api/anthropic

环境变量 = 存在操作系统里的键值对配置；密钥放环境变量里，避免写进代码泄露。国际版把 BASE_URL 换成 https://api.z.ai/api/anthropic 即可。

COMMANDS

别只当对话工具：常用命令速查

claude 启动交互模式
claude -c 继续最近的一次会话
claude -p 一次性提问，结束后自动退出
/init 用 CLAUDE.md 初始化项目说明
/clear 清空当前会话上下文，防止信息过载
/compact 压缩会话历史，减少 token 占用
/cost 查看当前消费情况
/model 切换使用的模型（兼容 API 时一般可忽略）
/help 显示可用命令列表
Ctrl+C 退出 Claude Code

完整命令表见官方文档：CLI Reference 与 Slash Commands；高级功能还有 /agents 与 /mcp。

CLAUDE.MD

CLAUDE.md：项目的记忆文件

它是什么
启动对话时自动读取，加入上下文
  • 常用 bash 命令、核心文件与工具函数
  • 代码风格约定、测试方式说明
  • 仓库协作规范（分支命名、merge / rebase）
  • 开发环境配置、项目坑点
  • 任何你希望 Claude「记住」的信息
示例（没有强制格式）
# Bash commands - npm run build: Build the project - npm run typecheck: Run the typechecker # Code style - Use ES modules (import/export) syntax # Workflow - Be sure to typecheck when you're done - Prefer running single tests, not the whole suite

只要简洁、便于人类阅读即可——记得越具体，AI 的表现越稳定。

HOW IT WORKS

为什么它更好用：感知—思考—行动—验证

Stream
流式处理
一边思考一边输出，不等全部写完再执行
Compress
智能压缩
把长对话历史压缩成关键信息，减少遗忘
Parallel
并发控制
内部并行设计，多个任务同时推进互不干扰
Sub-Agent
子 Agent 管理
多个子 Agent 分工协作：测试、文档各有所司

模仿人类开发者的工作流：不断「写代码 → 运行 → 看结果 → 再改进」，根据工具返回的真实结果决定下一步。其他 CLI 工具的实现大体类似。

CODEX

Codex：OpenAI 版的 Claude Code

它是什么
最大优势：对 GPT-5 的高效适配
  • GPT-5 响应速度更快、犯错率更低
  • 多轮复杂任务中正确完成的概率更高
  • 缺点：解释偏学术、信息量大，对初学者略难懂
# 安装 Codex npm i -g @openai/codex
两种后端
官方 API 或转发 API
  • 官方 API：输入 codex 按提示完成登录即可
  • 转发 API：第三方平台买配额，避开价格与网络限制
  • 配置 config.toml + 环境变量（可交给 Trae 完成）
  • codex --profile myrelay 启动转发模式

注意：转发平台的密钥分组要选「Codex 专用」那一项。

配好之后用法和 Claude Code 类似：在对话框里随时输入你的想法和需求即可。

OPENCODE

OpenCode：多模型版的 Claude Code

它是什么
开源的 AI Coding Agent 平台
  • Terminal 为核心入口，也支持 VS Code / Neovim
  • 自由切换 GPT / Claude / Gemini 乃至本地模型
  • OpenAI 官方也支持 OpenCode 接入 Codex 订阅
# Linux / Unix curl -fsSL https://opencode.ai/install | bash # Windows npm i -g opencode-ai
上手两步
免费模型 + 第三方模型
  • 输入 opencode 启动，进入聊天面板
  • /models 搜 free 关键词，用免费模型
  • /connect 浏览器授权，接入第三方模型
  • 免费模型高峰期较慢，付费 / 订阅模型更稳

核心优势：同样的 MCP、Skills、上下文配置下，自由切换模型完成不同编码任务。

TIPS & TRICKS

OpenCode 进阶配置与日常技巧

opencode.json 精细控制模型：categories 按任务自动选模型——简单修改用快模型省钱，复杂架构用强模型保质
MCP 扩展：chrome-devtools（操作浏览器、截图分析 UI）、zai-mcp-server，配完重启即可在对话中自动调用
AGENTS.md 指导 AI 行为：项目约定、开发流程、禁止事项，每次启动自动读取
常见问题：命令找不到 → 把 npm 全局目录加进 PATH 后重启终端；响应慢 → 走 quick 分类或开新会话

不熟悉一个项目时，可以让它并行探索：同时搜索 HTTP 请求、数据库代码、目录结构，一次给你完整的代码库地图。

SPECIFY YOUR NEEDS

用 AI 写需求文档：学会「具体化」

抽象需求
「我很饿」
  • 「帮我写个每天记计划并提醒的应用」
  • AI 可以直接拆任务做，但中间易出错
  • 理解偏差，返工成本高
具体化之后
「一个红豆面包，再配一杯豆浆」
  • 第一步：让 AI 把想法扩写成详细 PRD
  • 第二步：让 AI 按 PRD 开发，结构更稳定
  • 不确定的模块，让 AI 给备选方案再挑选合并

对 AI 开发来说，「具体」就是生产力。长提示别每次重打——沉淀为 markdown 需求文档，迭代复用，文档越完善，代码实现越成熟。

BEYOND CODING

不止是写代码

管理文件夹：一句话让 AI 把杂乱文件按内容、按时间归类整理
开发新项目：和 z.ai / Trae 用法相同，提前准备需求文档，越细效果越好
部署开源项目：把 GitHub 链接扔给 Claude Code，自动拉取、配环境、启动 Dify
讲解代码与写文档：让 AI 读项目、出结构化分析文档，保存为 markdown

一个对话框 + 喝一杯咖啡的时间 ☕️——大部分常见 GitHub 开源项目都能这样跑起来。
